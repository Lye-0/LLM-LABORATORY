## まず一本の流れをつかむ

LLMは、文章をトークンIDへ変換し、学習された重みを使って数値計算を行います。その結果から次のトークンを選び、列の末尾へ追加します。この繰り返しが文章の生成です。

```text
文字列 → Tokenizer → ID列 → 整数Tensor
                              ↓
                         Embedding
                              ↓
                      Transformerの各層
                              ↓
                    Logits → 次のIDを選ぶ
                              ↓
                      列に追加 → 繰り返す
```

## 三つの担当を区別する

| 担当 | 受け取るもの | 主な結果 |
|---|---|---|
| Tokenizer | 文字列・会話 | トークンID列 |
| モデル | IDのTensorとmaskなど | 各位置の次トークン候補のlogits |
| 生成処理 | logitsと設定 | 選んだID、停止の判断 |

VocabularyはTokenizerが持つ対応表です。Embeddingはモデル側の学習可能な表です。どちらも「表」ですが、一方はトークンと整数の対応、もう一方は整数からベクトルを取り出すための重みです。

## 数値の姿を追う

文章が7トークンになり、1件をまとめて処理すると仮定します。Bはbatch、Tはsequence、Dはhidden dimension、Vはモデルの出力候補数です。

| 段階 | shapeの例 | 中身 |
|---|---|---|
| input_ids | [1, 7] | 整数の識別番号 |
| Embedding後 | [1, 7, D] | 各位置のベクトル |
| Transformer後 | [1, 7, D] | 文脈を反映した表現 |
| logits | [1, 7, V] | 各位置の次トークン候補のスコア |

次の1トークンを生成するときは、通常、最後の位置のlogitsを使います。モデルによって出力を一部だけ計算する最適化もあるため、この表は基本形です。

## 推論と学習

推論では通常、重みを固定して入力から出力を計算します。学習では、正解とのずれを損失で測り、勾配に沿って重みを更新します。「会話の続きを入力する」ことと「学習で重みを更新する」ことは別です。

モデルを改造するには、まずどこを変更するのかを特定し、同じ条件の入力で変更前後を比較します。生成文だけでなく、shape、メモリ、速度、評価指標も観察対象になります。
