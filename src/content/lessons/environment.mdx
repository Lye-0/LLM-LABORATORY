## どこで動くかを選ぶ

| 環境 | 得意なこと | 必要なもの |
|---|---|---|
| ブラウザー | 小行列、shape、語彙の観察 | このサイト |
| Python + CPU | PyTorchの基本、参照値の検証 | Python、uv |
| Python + CUDA | 実モデルの推論・学習 | 対応GPU、ドライバー、対応版のPyTorch |

## uvで実験を分離する

新しいフォルダーで、依存関係を管理するプロジェクトを作ります。

```bash
uv init --python 3.13
uv add torch transformers accelerate
uv run python -c "import torch; print(torch.__version__)"
```

表示される版は導入時の解決結果によります。再現する実験ではpyproject.tomlとuv.lockを保存します。CUDA用のインストール方法はOS・ドライバー・PyTorch版に依存するので、PyTorch公式の対応表に合わせます。

## CPUとCUDAを確認する

```python
import torch

x = torch.tensor([1, 2, 3])
print(x.device)
print(torch.cuda.is_available())
```

```text
cpu
False
```

これはCUDAを利用できない環境の出力例です。TrueならCUDAが使える状態ですが、モデル全体がGPUメモリへ収まることまでは保証しません。

## WSLとエディターの実行先

WindowsのVS CodeからWSL内のPythonを使う場合、Remote WSLでフォルダーを開き、Python interpreterもWSLの仮想環境を選びます。Windows側のPythonとWSL側のPythonでは、導入済みパッケージが異なります。補完が出ないときは、実行に使う環境と解析に使う環境を照合します。

### コードは動くのに、補完や型表示がおかしいとき

次の順に確認します。

1. **VS Codeの接続先**：ウィンドウのリモート接続表示が`WSL: Ubuntu`など対象のディストリビューションになっているか確認します。ターミナルでWSLを開けることだけでは、エディターの接続先まで同じとは限りません。
2. **拡張機能の実行先**：拡張機能画面のLocalとWSLの区分を確認します。Python/Pylanceなど、WSL側で必要な拡張が使える状態にします。
3. **選択したPython**：コマンドパレットの`Python: Select Interpreter`で、プロジェクトの`.venv/bin/python`を選びます。
4. **実際に動いたPython**：次のコードを、VS CodeのPython実行機能と、普段使う`uv run python`の両方で実行し、同じ環境を使っているか比べます。

```python
import sys
import torch

print("Python:", sys.executable)
print("PyTorch:", torch.__version__)
print("torchの場所:", torch.__file__)
```

最初の行は実行中のPython、最後の行は読み込んだtorchの場所です。具体的なパスは端末によって変わります。WSLで実行しているつもりなのにWindows側のPythonが表示されたり、想定外の仮想環境が表示されたりしたら、実行方法とinterpreterの選択を見直します。

### WSL側の拡張は、毎回入れ直すものではない

画面のテーマなどはローカル側、言語解析などはWSL側で動く場合があります。必要な拡張は対象のWSL環境へ導入しますが、通常は起動のたびに導入し直す必要はありません。別のディストリビューションでは別途準備が必要になる場合があります。初回接続時にはVS Code Serverのセットアップが行われます。[VS CodeのWSL開発ガイド](https://code.visualstudio.com/docs/remote/wsl)

### Anyという表示と、実行時の型

ホバーに`Any`と出るのは、静的な解析で型を特定できていない場合などの表示です。実物が型を持たないという意味ではありません。環境が正しくても、動的な実装などで解析しきれない箇所はあります。

```python
import inspect
from torch import nn

embedding = nn.Embedding(5, 3)
print("type(embedding):", type(embedding))
print("nnはモジュール:", inspect.ismodule(nn))
print("nn.Embeddingはクラス:", inspect.isclass(nn.Embedding))
```

```text
type(embedding): <class 'torch.nn.modules.sparse.Embedding'>
nnはモジュール: True
nn.Embeddingはクラス: True
```

これなら、そのPython環境で実際に作られたものを確認できます。`variable`と`instance`、`type`と`inspect`の読み分けは[Pythonでオブジェクトを読む](../python-objects/)へ戻って確認できます。

## 保存する情報

Python・torch・transformersの版、モデルrevision、dtype、device、seed、実行コードを記録します。GPUの型やdriverも性能比較に必要です。重みや仮想環境はGitへ入れず、コード・lockfile・小さな結果を管理します。

```bash
uv sync --frozen
```

これはlockfileに基づいて環境をそろえる操作です。別のOSやGPUでは、同じ乱数seedでも浮動小数点の結果が完全一致するとは限りません。
