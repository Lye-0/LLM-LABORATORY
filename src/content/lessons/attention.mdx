## 入力から三つの表現を作る

各位置の表現Xを異なる重みへ通し、Q（Query）、K（Key）、V（Value）を作ります。QとKで位置同士のスコアを計算し、そのスコアから得た重みでVを混ぜます。名前は役割の比喩で、辞書のキー・値とは別です。

| 表現 | 役割 | どこで使うか |
|---|---|---|
| Q：Query | 情報を集める側の比較用ベクトル | 各位置のKとのスコアを作る |
| K：Key | 参照先を照合するベクトル | Qと比較される |
| V：Value | 集める情報のベクトル | 決まった割合で重み付けして足す |

3つとも、各Token位置の**同じ正規化後のHidden State**から、別々のLinearで生成します。`Q → K → V`という直列処理ではありません。Vも学習済み射影の結果で、元のHidden Stateそのものではありません。

## Token・Head・成分を区別する

以下はQwen3-0.6Bに、paddingなし・1件・7 Tokenを入力する例です。RoPE後のQは`[1,16,7,128]`で、軸は`[Batch, Head, Token, 成分]`です。

| 取り出す式 | shape | 見ているもの |
|---|---|---|
| `q_rotated` | `[1,16,7,128]` | 16 Headそれぞれに7位置のベクトル |
| `q_rotated[0,2]` | `[7,128]` | Q Head 2の全Tokenを並べた行列 |
| `q_rotated[0,2,3]` | `[128]` | そのHeadのToken位置3のベクトル |
| `q_rotated[0,2,3,0]` | `[]` | そのベクトルの成分0のスカラー |

「Q Head 2」と「Token位置2」は別の指定です。このページのQₚ・Kₜの添字p・tはToken位置を表します。7 Tokenの位置は0〜6です。

## 1. スコアを作る

`scores = Q @ K.T / sqrt(d_k)`。Qのある行と、Kの各行の内積を取ります。d_kはhead内の成分数です。成分数によるスコアの大きさの変化を調整します。

RoPEを使うQwen3では、この式のQ/Kは位置に応じた回転を終えたものです。1つのスコアは1 head全体の内積で、回転ペアごとの独立したスコアではありません。「RoPE & Relative Position」の実験では、回転から内積までを7×7表で追えます。

```text
1つのQ Head                    対応するK Head
Q [7,128] × Kᵀ [128,7] → 内積 [7,7]
                              ↓ 各要素を√128で割る
                           scores [7,7]
                              ↓ Mask → 行ごとにSoftmax
                                A [7,7]
                              ↓ A × V [7,128]
                           出力 [7,128]
```

`Kᵀ`の各列は、**1つのTokenの128成分**です。`scores[2,2]`を計算するときに足すのは、Q位置2とK位置2の対応する128成分の積です。他のTokenのKは混ざりません。行列積は、この内積を全位置の組についてまとめて計算します。

`Kᵀ @ Q`なら`[128,128]`になりますが、それはToken同士の7×7表とは別の計算です。4軸のTensorでは`.T`ではなく`transpose(-2,-1)`で末尾の2軸だけを交換します。

## 2. 参照できない位置を隠す

次トークン予測では、未来の位置に大きな負値（理想化すると−∞）を置きます。softmax後にその確率が0になるようにする処理です。paddingの位置を除くmaskとは目的を分けます。

**入力済みのプロンプトにも、各位置より後ろのTokenは存在します。** Qwen3は存在する値を意図的に参照対象から外します。最後の位置6は位置0〜6をすべて参照できるので、プロンプト全体の情報を使って次Tokenを予測できます。[PrefillとDecodeの違い](../kv-cache/#プロンプトはまとめて処理できる)で全体像を確認できます。

行列積で未来側のスコアを計算しても、その値をMaskで除外してから割合を決めれば、未来のVは出力へ入りません。Maskは参照範囲、Softmaxは割合を決める処理です。

## 3. softmaxで行ごとに正規化する

各Query位置について、参照するKey位置の重みの合計を1にします。softmaxは各要素の指数を取り、全体の和で割ります。実装では最大値を引いてから指数を計算すると、数値のオーバーフローを抑えられます。

## 4. Vの加重和を作る

```python
import torch
import math

q = torch.tensor([[1., 0.], [1., 1.]])
k = torch.tensor([[1., 0.], [0., 1.]])
v = torch.tensor([[2., 0.], [0., 4.]])
scores = q @ k.T / math.sqrt(2)
mask = torch.triu(torch.ones(2, 2, dtype=torch.bool), diagonal=1)
scores = scores.masked_fill(mask, float("-inf"))
weights = torch.softmax(scores, dim=-1)
print(weights)
print(weights @ v)
```

```text
tensor([[1.0000, 0.0000],
        [0.5000, 0.5000]])
tensor([[2., 0.],
        [1., 2.]])
```

位置0は自分だけを参照できます。位置1ではQと両方のKの内積が同じなので、Vを半分ずつ混ぜます。

割合はVの各Tokenのベクトルに掛けます。例えば`[0.6,0.1,0.3]`なら、`0.6×V₀ + 0.1×V₁ + 0.3×V₂`です。同じ割合をそのVの全成分へ掛け、成分ごとに足します。1つの割合をV Head全体へ掛けるわけではありません。

<details>
<summary>Maskのコードを分解する</summary>

| コード | 行っていること |
|---|---|
| `torch.ones(T,T,dtype=torch.bool)` | 全マスTrueの表を作る |
| `torch.triu(...,diagonal=1)` | 主対角線より上だけTrueを残す |
| `scores.masked_fill(mask,float("-inf"))` | Trueのスコアを−∞へ置き換えた新しいTensorを返す |
| `torch.softmax(...,dim=-1)` | 各Q位置について、K位置の軸で割合を計算する |

`diagonal=1`なので、自分自身にあたる対角線は除外しません。`[7,7]`のmaskはbroadcastによって`[1,16,7,7]`の全Headへ適用できます。GPUなら`device=scores.device`で同じ配置先に作ります。

このmaskはpaddingなし・cacheなしの正方形の例です。KV Cache使用時はQとKの位置数が異なるため、絶対位置や過去の長さを考慮します。また、boolの意味はAPI依存です。`masked_fill`ではTrueを置換しますが、PyTorchの`scaled_dot_product_attention`へ渡すbool maskではTrueが参照許可を表します。

</details>

## Attention mapの読み方

マップの値は、この層・head・入力における重みです。「モデルがその単語を人間の意味で重視した」「これが回答の唯一の原因」とは断定できません。複数のhead、層、Residualなどを通して最終出力が決まります。

## 複数headとGQA

headごとに別の表現で情報を集め、結合して出力へ写します。GQAでは複数のQuery headがKey/Value headを共有します。QとKVのhead数を同じと決めつけず、モデル設定から各shapeを読みます。

Qwen3-0.6BではQが16 Head、KとVが各8 Head、1 Headは128次元です。

| Q Head | 使うK Head | 使うV Head |
|---|---|---|
| 0・1 | 0 | 0 |
| 2・3 | 1 | 1 |
| … | … | … |
| 14・15 | 7 | 7 |

Q Head番号を`h`とすると、K/V Head番号は`h // 2`です。「共有」はKとVが同じ値になることではありません。同じK/Vを使ってもQが異なるため、参照割合や出力は異なり得ます。出力はQに対応して16 Head分できます。

<details>
<summary>repeat_interleaveとrepeatでは、共有する順番が違う</summary>

```python
head_ids = torch.tensor([0, 1, 2, 3])
print(head_ids.repeat_interleave(2))  # [0,0,1,1,2,2,3,3]
print(head_ids.repeat(2))             # [0,1,2,3,0,1,2,3]
```

Qwen3のHead軸では`repeat_interleave(2,dim=1)`に相当する対応を使います。`repeat(1,2,1,1)`では全Headの並びを繰り返すため、shapeが同じでもQとの組み合わせが変わります。別の対応規則なら`index_select`などでも表現できますが、学習済みモデルの規則に合わせる必要があります。高速実装は物理的な複製を省く場合があります。[repeat_interleave](https://docs.pytorch.org/docs/2.14/generated/torch.repeat_interleave.html)・[repeat](https://docs.pytorch.org/docs/2.14/generated/torch.Tensor.repeat.html)

</details>

## Concat・o_projからHidden Stateへ

```text
各Headの出力 [1,16,7,128]
  ↓ transpose(1,2)：Token軸を先へ
             [1,7,16,128]
  ↓ Concat：各Tokenの16×128成分を連結
             [1,7,2048]
  ↓ o_proj：学習済みweight [1024,2048] の転置を掛ける
             [1,7,1024]
  ↓ Input RMSNorm前のHidden Stateと加算
Attention後  [1,7,1024]
  ↓ さらにRMSNorm → MLP → 2回目の残差接続
Layerの出力  [1,7,1024]
```

Concatは足し算や平均ではなく連結です。続く`o_proj`は、2048成分を学習済みの行列で混ぜ合わせて1024成分へ写します。単に半分を削る処理ではありません。結果は元のHidden Stateへ加算され、Qそのものへ書き戻されるわけではありません。

## RoPE後からの手動観察コード

次は[位置情報とRoPE](../position/#qwen3のコードへつなぐ)で取得した`q_rotated`・`k_rotated`と、同じ入力の`v_heads`を使う続きです。**1件・paddingなし・cacheなし・evalモード**の観察用で、一部をfloat32で計算します。

```python
with torch.no_grad():
    B, Hq, T, D = q_rotated.shape
    Hkv = k_rotated.shape[1]
    assert Hq % Hkv == 0
    repeats = Hq // Hkv
    k_expanded = k_rotated.repeat_interleave(repeats, dim=1)
    v_expanded = v_heads.transpose(1, 2).repeat_interleave(repeats, dim=1)

    kt = k_expanded.float().transpose(-2, -1)
    scores_raw = q_rotated.float() @ kt
    scores = scores_raw / (D ** 0.5)
    future_mask = torch.triu(
        torch.ones(T, T, dtype=torch.bool, device=scores.device), diagonal=1
    )
    masked_scores = scores.masked_fill(future_mask, float("-inf"))
    weights = torch.softmax(masked_scores, dim=-1)
    heads = weights @ v_expanded.float()
    joined = heads.transpose(1, 2).contiguous().reshape(B, T, Hq * D)
    projected = attention.o_proj(joined.to(attention.o_proj.weight.dtype))
    after_attention = before_norm + projected

print("K転置後:", kt.shape)        # [1,16,128,7]
print("scores:", scores.shape)     # [1,16,7,7]
print("行の合計:", weights.sum(-1))  # 各行がおおむね1
print("残差後:", after_attention.shape)  # [1,7,1024]
```

`matmul`はMatrix Multiplication（行列積）の略で、ここでは`@`と同じ計算です。たとえば`scores[0,2,3,1]`はQ Head 2・位置3と、共有元のK Head 1・位置1の128成分の内積を√128で割った値です。手動の`torch.dot`とも比較できます。

スコアや割合は計算途中のTensorで、KV Cacheとは別です。高速なAttentionは全スコアを独立したTensorとして保存しない場合があります。手動計算はdtypeや演算順が公式経路と異なり得るので、モデル出力との比較では誤差も記録します。`after_attention`はMLP前であり、Layer 0全体の出力`hidden_states[1]`とは比較地点が異なります。

構造・shapeは[参照Qwen3実装](https://github.com/huggingface/transformers/blob/v5.18.0/src/transformers/models/qwen3/modeling_qwen3.py)と[固定config](https://huggingface.co/Qwen/Qwen3-0.6B/blob/c1899de289a04d12100db370d81485cdf75e47ca/config.json)に基づきます。
