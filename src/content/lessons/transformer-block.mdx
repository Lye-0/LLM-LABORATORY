## 一つのブロックの基本形

Qwen系のpre-normブロックを模式的に表すと、正規化してAttentionを計算し、元の入力へ足します。その結果を正規化してMLPへ通し、もう一度足します。

```text
x ────────────────┐
↓ RMSNorm         │
Attention         │
↓                 │
加算 ←────────────┘
↓                 ┐
RMSNorm           │
MLP               │
↓                 │
加算 ←────────────┘
```

## Residual — 元の表現を足す

```python
import torch
x = torch.tensor([[1., 2.]])
change = torch.tensor([[0.2, -0.3]])
print(x + change)
```

```text
tensor([[1.2000, 1.7000]])
```

元の情報を保つ経路を作り、変換が加える差分と組み合わせます。加算できるshapeであることが重要です。

## RMSNorm — スケールを整える

特徴軸の二乗平均から得た大きさで割り、学習可能な係数を掛けます。LayerNormのように平均を引く操作とは区別します。epsilonはゼロ除算を避けるための小さな値です。

RMSはRoot Mean Square（二乗平均平方根）の略です。この正規化は入力のスケールを整える計算で、optimizerが学習中に重みを更新する「最適化」とは別です。

`yᵢ = weightᵢ × xᵢ / √(mean(x²) + ε)`。例えばεとweightを省いた`[1,2,2]`の正規化なら、RMSは√3で、結果は約`[0.577,1.155,1.155]`です。必ず値を小さくする処理でも、0〜1へ収める処理でもありません。

RMSで割る段階は同じベクトルの全成分へ共通の倍率を掛けます。その後の学習済みweightは成分ごとに違い、比率・向き・符号も変わり得ます。

| Qwen3のNorm | 正規化する単位 | weightのshape |
|---|---|---|
| input_layernorm | 各Tokenの1024成分。Attentionへ渡す前 | `[1024]` |
| q_norm / k_norm | 各Token・各Headの128成分 | 各`[128]` |
| post_attention_layernorm | 1回目の残差加算後の1024成分。MLPへ渡す前 | `[1024]` |
| model.norm | 全Decoder Layer通過後の1024成分 | `[1024]` |

各モジュールは別のweightを持ちます。Q Normでは各Headで別々のRMSを求めますが、同じ`q_norm.weight`を位置とHeadに共通で使います。V専用のQ/K Normはありません。

<details>
<summary>RMSNormを基本演算で再現する</summary>

[Qwenの観察](../qwen/)で得た`hidden_states`と`model`を使います。

```python
norm = model.model.layers[0].input_layernorm
before_norm = hidden_states[0]
with torch.no_grad():
    x = before_norm.float()
    mean_square = x.pow(2).mean(dim=-1, keepdim=True)
    inverse_rms = torch.rsqrt(mean_square + norm.variance_epsilon)
    normalized = x * inverse_rms
    manual = norm.weight * normalized.to(before_norm.dtype)
    actual = norm(before_norm)
print(mean_square.shape)  # [1,7,1]：各Tokenにつき1個
print(manual.shape)       # [1,7,1024]
print(torch.allclose(manual, actual))
```

`rsqrt`は逆平方根です。`keepdim=True`で末尾の長さ1の軸を保つので、1024成分へbroadcastできます。`norm(before_norm)`は保存値の取得ではなく、そのモジュールをもう一度実行する呼び出しです。`output_hidden_states=True`でモデル全体を実行した後に、一部分だけ再実行して観察しています。

</details>

## MLPとSwiGLU

MLPは各トークン位置のベクトルを広い特徴空間へ写し、非線形変換後に元の次元へ戻します。Qwenではgateとupの二つの投影を使うSwiGLU系の構造を観察できます。

```text
gate = silu(gate_proj(x))
up   = up_proj(x)
output = down_proj(gate * up)
```

これは構造の模式コードです。実物のbiasやshapeはconfigとmoduleを確認します。

Qwen3-0.6BのMLPでは、gateとupは同じ正規化後の入力から分岐し、別々の重みを使います。

| 処理 | shape（1件・7 Token） | 計算の意味 |
|---|---|---|
| post_attention_layernorm | `[1,7,1024]` | MLPへ渡す入力を正規化 |
| gate_proj / up_proj | 各`[1,7,3072]` | 同じ入力を別々に線形変換 |
| SiLU(gate) | `[1,7,3072]` | `x × sigmoid(x)`を各成分へ適用 |
| SiLU(gate) * up | `[1,7,3072]` | 対応成分を掛ける。行列積ではない |
| down_proj | `[1,7,1024]` | 元の幅へ線形変換 |
| 2回目の残差加算 | `[1,7,1024]` | MLP前のNormより前の値へ加える |

SiLUの値は負にも1より大きくもなるので、gateは0〜1の確率ではありません。Token数は7のままで、同じMLPを各位置へ適用します。

### up・gate・SiLUは何をしている？

Attentionが位置同士から情報を集めるのに対し、MLPは**各位置に集まった情報の、成分の組み合わせを変える**処理です。Attention後の入力なので、MLPも文脈を反映した値を扱っています。

| 部品 | 役割 | 区別する点 |
|---|---|---|
| up_proj | 入力の1024成分を組み合わせ、3072成分の中間表現を作る | 成分をコピーして増やす処理ではない |
| gate_proj → SiLU | 同じ入力から、upの各成分に掛ける値を作る | upの結果を読んで判断する枝ではない |
| 要素積 | upとSiLU(gate)の対応成分を掛ける | この段階では成分同士を足し合わせない |
| down_proj | 3072成分を重み付きで組み合わせ、1024成分へ戻す | 先頭1024成分だけを残す処理ではない |

**upとgateは並列**です。別々の学習済み重みで同じ入力を変換し、gate側だけにSiLUを適用してから掛け合わせます。SiLU自体は固定の関数で、学習する重みは持ちません。「通す量」は直感的な呼び方で、人間が理解する重要度や確率そのものではありません。

### 1成分だけで見る、小さな計算例

以下は仕組みを説明する仮の値です。実際のモデルの観測値ではありません。

| upの値 | gate_projの値 g | SiLU(g) = g × sigmoid(g) | SiLU(g) × up |
|---|---|---|---|
| 2 | 2 | 約1.7616 | 約3.5232 |
| 2 | −2 | 約−0.2384 | 約−0.4768 |

同じupの値でも、gate側の値によって大きさや符号が変わります。実際には3072成分それぞれでこの計算を行い、その後down_projが成分を混ぜます。特定の成分が必ず「文法」「天気」など一つの意味を担当する、という対応は保証されません。

<details>
<summary>幅を広げることと、非線形にすることは別</summary>

幅を広げると、中間表現を作る成分数が増えます。ただし、新しい情報を外から追加するわけでも、幅が3倍なら能力も3倍になるわけでもありません。

線形変換だけを重ねた`(x @ W₁) @ W₂`は、`x @ (W₁ @ W₂)`という一つの線形変換にまとめられます。SwiGLUではSiLUと、入力に依存する二つの枝の掛け合わせにより、この形では表せない変換を作ります。SiLUだけを外しても、gateとupの要素積が残るので全体が線形になるわけではありません。

</details>

ここまでのgate・up・SiLU・要素積・downを含む部品が`layer.mlp`で、その実行結果のTensorが`mlp_output`です。MLP前のNormと、次の残差加算はMLPモジュールの外側にあります。[行列積・要素積・加算の比較](../linear/#行列積要素積加算を区別する)も併せて確認できます。

## 2回の残差接続をコードで区別する

```text
x：層に入ったHidden State
a = x + SelfAttention(input_layernorm(x))
y = a + MLP(post_attention_layernorm(a))
```

1回目で足すのは`x`、2回目で足すのは`a`です。それぞれのNorm後の値を残差として足すのではありません。

式を展開すると「層の入力 + Attentionの出力 + MLPの出力」ですが、MLPは**1回目の加算結果aを正規化した値**から計算します。三つを独立に計算して最後に足す構造ではありません。

<details>
<summary>Attention観察の続きでMLPと残差を確認する</summary>

[Attentionの手動観察](../attention/#rope後からの手動観察コード)で作った`after_attention`と`layer0`を使います。

```python
with torch.no_grad():
    mlp = layer0.mlp
    mlp_input = layer0.post_attention_layernorm(after_attention)
    gate = mlp.act_fn(mlp.gate_proj(mlp_input))
    up = mlp.up_proj(mlp_input)
    mlp_output = mlp.down_proj(gate * up)
    layer0_output = after_attention + mlp_output
    print(torch.allclose(mlp_output, mlp(mlp_input)))
```

MLP単体を同じ入力で比べる検証と、Layer全体を`outputs.hidden_states[1]`と比べる検証は別です。後者では入力・model.eval()・dtype・Attention実装をそろえ、最大絶対誤差なども記録します。手動Attentionでfloat32を使う経路は、本体の演算と完全一致するとは限りません。

</details>

## 重ねることで表現を変える

一つのブロックの入力と出力が同じshapeでも、中の数値は変わります。28層なら同じ構造の計算を28回重ねますが、各層のパラメータが全部同じという意味ではありません。位置ごとのhidden stateが段階的に変換されます。

| 観察位置 | outputs.hidden_statesとの対応 |
|---|---|
| Layer 0の入力 | `[0]`：Embedding後 |
| Layer 0の1回目の残差加算後 a | 層の途中の値。通常のhidden_states tupleには個別に入らない |
| Layer 0の出力 y → Layer 1の入力 | `[1]` |
| Layer 1の出力 → Layer 2の入力 | `[2]` |

このページの`x・a・y`は1層の途中経過を区別する名前です。`hidden_states[0]・[1]・[2]`という層ごとの記録番号とは区別してください。

[実際のQwenを観察する](../qwen/)では、`hidden_states[0]`（Embedding後）と`hidden_states[1]`（Layer 0後）の同じ位置を比べます。どちらも`[1,7,1024]`ですが、数値は異なります。今回のQwen3では最後の`hidden_states[-1]`に全28層の後の最終RMSNormも含まれるため、最後のLayerだけの出力とは区別します。上の1ブロック内の二つのNormと、この最終Normは別の部品です。

## 改造の入口

1層から全体へ進む場合は、[28層の連続処理と最終RMSNorm](../decoder-stack/)で、最後の層の出力と最終Norm後の値を分けて観察できます。

層を外したり、MLPを置換したりするなら、Residualへ戻すshape、dtype、deviceを維持する必要があります。実行できることと、品質が保たれることは別の検証です。

実装の確認先：[Qwen3MLP / Qwen3DecoderLayer（Transformers v5.18.0）](https://github.com/huggingface/transformers/blob/v5.18.0/src/transformers/models/qwen3/modeling_qwen3.py)、[PyTorchのSiLU](https://docs.pytorch.org/docs/2.14/generated/torch.nn.SiLU.html)。
