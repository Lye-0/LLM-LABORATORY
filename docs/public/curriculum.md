# カリキュラム

学習範囲と到達目標の定義。各教材の実装は `src/content/lessons/`、実験の実装範囲は `src/data/catalog.ts` と公開教材の表示を確認する。計画にある実モデルの学習・性能測定をすべて実行済みと扱わない。

## 1. 学習の道筋

中心となる流れは、**文章 → ID → Tensor → Embedding → Transformer → Logits → 次トークン → 学習 → 評価 → 改造**。

以下のIDは制作・関連付け用。公開タイトルに実験番号を強制しない。教材は一度読んで終える長さに分け、必要な詳説は同じ主題の節・辞書・実験へつなぐ。

各単元には「前提」「説明できるようになること」「小さなコードと結果」「観察または確認問題」「次の接続」を用意する。最低でも中心例1組と、混同しやすい比較1組を持つ。

## 2. 全体と実行環境

| ID  | 教材                                   | 前提         | 到達目標・演習                                                           |
| --- | -------------------------------------- | ------------ | ------------------------------------------------------------------------ |
| A01 | LLMの全体像 — 文章から次のトークンまで | なし         | Tokenizer・モデル・生成処理を区別し、全体の流れを説明する                |
| A02 | Pythonでオブジェクトを読む             | Pythonの代入 | モジュール・クラス・変数・インスタンス・メソッド・返り値を小例で区別する |
| A03 | 学習環境を用意する                     | A02          | uv、仮想環境、CPU/CUDA、WSL、VS Codeの実行先を確認する                   |
| A04 | 小さなモデルをロードして生成する       | A01・A03     | model/tokenizer/configの役割を分け、入力と生成部分を切り分けてdecodeする |

A04は先に全体を動かす入口。全内部構造の理解を前提にせず、入力shapeや生成設定から詳細教材へ戻れるようにする。GPUを持たない読者にはCPUの小例と記録済みの実測を用意する。

## 3. 文章をモデル入力にする

| ID  | 教材                                    | 前提     | 到達目標・演習                                                                    |
| --- | --------------------------------------- | -------- | --------------------------------------------------------------------------------- |
| B01 | Tokenizer — 文字列をIDへ変える          | A01・A02 | AutoTokenizerの読み込み、tokenize / encode / decode / `__call__` を比較する       |
| B02 | Vocabulary — トークンとIDの対応         | B01      | 辞書のキー、get_vocab、基本語彙と追加分、ID順の観察を説明する                     |
| B03 | Byte-level BPE — 文字とバイトと結合規則 | B02      | 内部表記・UTF-8・空白・文字断片を分け、小さな結合例を追う                         |
| B04 | 会話形式と特殊・追加トークン            | B01・B02 | Chat Template、role、EOS/PAD、specialフラグ、Thinkingの境界を区別する             |
| B05 | Tensor — 数値を形状・型・デバイスで扱う | A02・B01 | list→Tensor、shape / ndim / numel / element_size、スカラー・slice・itemを説明する |
| B06 | バッチとモデル入力の整形                | B04・B05 | unsqueeze、padding、truncation、attention_mask、CPU/GPU配置を比較する             |

例文には「こんにちは、今日はいい天気ですね」を残すが、一般的なサンプル文として扱う。英語・先頭空白・絵文字・改行も比較し、特定の文章の分割を一般仕様にしない。

## 4. ベクトルからTransformerへ

| ID  | 教材                                   | 前提          | 到達目標・演習                                                           |
| --- | -------------------------------------- | ------------- | ------------------------------------------------------------------------ |
| C01 | Embedding — IDをベクトルへ変える       | B02・B05・B06 | `nn.Embedding(5,3)`、行の参照、`[B,T]→[B,T,D]`、ランダム初期化を説明する |
| C02 | ベクトル・行列・Linear                 | C01           | 内積、行列積、転置、broadcast、`nn.Linear`、重みと活性値を区別する       |
| C03 | Self-Attention — Q・K・Vから出力を作る | C02           | スコア・スケーリング・causal mask・softmax・加重和を小行列で追う         |
| C04 | 位置情報 — 順序を扱う                  | C03           | 位置埋め込みとRoPEの違い、Q/Kに位置を反映する考え方を説明する            |
| C05 | Transformerブロックを読む              | C03・C04      | Residual、RMSNorm、MLP/SwiGLU、MHA/GQAを配置とshapeで理解する            |
| C06 | 実際のQwenの内部を観察する             | A04・C01      | モデル名・クラス・実物、学習済みEmbeddingの行参照、1・7トークンの出力、configと重み共有を読む |

基礎のAttentionは小さな標準例とし、QwenのGQAやhead_dimを同一視しない。Embeddingの固定ベクトルと、層を通った文脈依存のhidden stateを区別する。

## 5. 次のトークンを生成する

| ID  | 教材                   | 前提     | 到達目標・演習                                                         |
| --- | ---------------------- | -------- | ---------------------------------------------------------------------- |
| D01 | Logitsと確率           | C02・C05 | 最後の位置のlogits、softmax、候補の順位を説明する                      |
| D02 | Samplingと生成設定     | D01      | greedy、temperature、top-k、top-p、seed、EOS、max_new_tokensを比較する |
| D03 | 自己回帰生成とKV Cache | D02・C03 | prefillとdecode、1トークンずつ延長する流れ、キャッシュの役割を追う     |
| D04 | 推論時のメモリと速度   | B05・D03 | 重み・活性値・KV Cache、batchと文脈長、TTFTと生成速度を分けて測る      |

確率が最大の候補が必ず選ばれるのはgreedyなどの条件付き。temperatureを創造性や正確さの保証として説明しない。停止とdecode時の表示除去も分ける。

## 6. 学習で重みを変える

| ID  | 教材                       | 前提                         | 到達目標・演習                                                        |
| --- | -------------------------- | ---------------------------- | --------------------------------------------------------------------- |
| E01 | Autograd・Parameter・勾配  | C01・C02                     | requires_grad、grad_fn、leaf、backward、detachを小さな計算で追う      |
| E02 | 次トークン予測の損失と更新 | D01・E01                     | labelsのshift、cross entropy、mask、optimizer、zero_gradを理解する    |
| E03 | 学習データと評価の分離     | E02                          | train/validation/test、データ漏洩、過学習、perplexityの範囲を説明する |
| E04 | Fine-tuning・LoRA・QLoRA   | E02・E03（QLoRAはF01も前提） | 更新するパラメータの範囲、adapter、rank、量子化との関係を比較する     |

数学の補助教材として、行列のshape、softmax、対数、微分・連鎖律を用意する。先に数学講座全体を履修させず、必要な節から読めるようにする。

## 7. 圧縮・評価・モデル改造

| ID  | 教材                             | 前提               | 到達目標・演習                                                                  |
| --- | -------------------------------- | ------------------ | ------------------------------------------------------------------------------- |
| F01 | 数値精度と量子化                 | B05・C02・D04      | FP32/FP16/BF16、scale、zero point、group、丸め誤差、PTQ/QATの位置づけを説明する |
| F02 | 改造前後を評価する               | D02・E03・F01      | 同条件の品質・速度・メモリ比較、seed、評価データ、許容誤差を設定する            |
| F03 | モデル構造を調べて変更する       | C06・E01・F02      | hooks、state_dict、freeze、層の置換、ablation、shapeの契約を理解する            |
| F04 | TokenizerとEmbeddingを拡張する   | B02・B04・C06・E02 | 語彙追加、Embedding/lm_head整合、重み共有、追加行の学習を説明する               |
| F05 | 改造したモデルを保存・再読込する | F03・F04           | config、重み、Tokenizer、adapter、revisionをセットで管理し復元する              |

量子化の学習は小さな数列から始め、その後に実モデルを扱う。ビット数だけで速度・品質・実使用VRAMを決めつけない。独自の圧縮方式へ進む際は、復元処理と対応カーネルも実験対象になる。

## 8. 周辺技術の独立教材

| テーマ                   | 主題・接続                                                                                    |
| ------------------------ | --------------------------------------------------------------------------------------------- |
| 実行基盤の関係           | Transformers / PyTorch / Accelerate / CUDA、ドライバーと環境、device_mapと単一GPU             |
| 再現性と共同作業         | uv.lock、Python・ライブラリ版、Git/GitHub、モデルrevision、乱数と非決定性                     |
| モデルの配布形式         | safetensors、config、Tokenizer一式、GGUF、adapterの保存と互換性                               |
| 推論エンジン             | llama.cpp、Ollama、vLLMの役割と比較の観点。改造したPyTorch実装をそのまま使えるとは限らない    |
| RAG・検索用Embedding     | モデル内部のtoken embedding、文章埋め込み、検索、重みの変更の違い                             |
| Tool Use・マルチモーダル | 区切りトークン、外側の実行プログラム、画像エンコーダーなどの役割                              |
| データとモデルの利用条件 | 配布ライセンス、データ由来、再配布時の条件、モデルカードの読み方                              |
| 性能を調べる道具         | profiler、CUDA同期、warmup、peak memory、測定条件の記録                                       |
| 発展する研究テーマ       | 蒸留、pruning、sparsity、MoE、分散学習、FlashAttention、torch.compile。必要な前提と入口を示す |

初期の周辺教材は「役割・使う場面・中心テーマとの関係・公式資料」までを持つ。名前だけの空ページを大量に増やさない。

## 9. 改造課題

| 課題                          | 変更・観察                | 成果物と完了基準                                           |
| ----------------------------- | ------------------------- | ---------------------------------------------------------- |
| P01 内部を観察する            | module tree、hooks、shape | どの段階で表現が変わるかを説明できる観察表                 |
| P02 Embeddingの一部を変更する | 特定行を複製モデルで変更  | baselineとの差分、影響範囲、変更の復元                     |
| P03 LoRAで適応する            | 対象層とrankを変える      | 更新パラメータ数、検証損失、未使用データでの評価           |
| P04 量子化を比較する          | 精度・group条件を変える   | 同条件の品質・速度・メモリ比較。理論容量と実測を分ける     |
| P05 層を置換・無効化する      | 小モデルの一部をablation  | shape整合、推論成功、性能劣化を含む評価                    |
| P06 独自の改造を設計する      | 研究仮説を一つ選ぶ        | 仮説、baseline、変更、実験条件、結果、限界、再現手順、復元 |

各課題は小モデルで成立する入口を用意する。学習成績の改善を合格条件にせず、適切な比較と説明ができることを重視する。
