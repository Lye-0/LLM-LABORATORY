# 教材の編集方針

## 理解する順に並べる

対象の役割と全体の位置づけから始め、import、設定、インスタンス、入力を用意してから処理例を示す。実験した時系列や作業ログをそのまま説明の順番にしない。

一つの教材は、一つの独立した学習単位を扱う。前提の短い説明は本文に残し、詳しい復習へリンクする。前提の全講義を毎ページに重複させない。

## コードと結果の単位

| 場面                                 | まとめ方                                             |
| ------------------------------------ | ---------------------------------------------------- |
| tokenize、encode、decodeなど別の処理 | 各処理のコード → 対応する結果 → 読み取り             |
| 同じTensorの値・型・shape・device    | 同じ小見出しの中へ集約                               |
| 同じ変数を更新する                   | 更新前と更新後のどの状態かを明示                     |
| 大きなオブジェクト表示               | 主要部分をコードブロックに置き、全文はその直下で展開 |

分割の単位はprintの数ではなく、理解する対象と処理で決める。確認式は `type(tensor)`、`tensor.shape` のように対象を含めて示す。コード・出力・確認表で名前と順番をそろえる。

代入や保存など、画面出力のない処理にも何が作られたか・変わったかを書く。「全文」と表示する欄は省略せず、抜粋や整形をした箇所は区別する。

## 根拠を区別する

- **実測**：コードと環境が特定できる実行結果。モデルrevision、ライブラリ、dtype、device、必要ならseedを記録する。
- **説明用の固定値**：仕組みを追いやすくするために与えた値。学習済みの意味表現や初期乱数の再現値としない。
- **仕様例**：仕様から説明する例。未実行なら実測と表示しない。
- **模式図**：処理の役割を単純化した図。実際の速度や内部値を測った表示としない。

入力・設定・コードを変えたら、古い出力を無条件に使い回さない。乱数、実行時間、生成文は、常に同じ値が再現するとは説明しない。

## 一覧と詳細

APIはライブラリ・所有者・用途で分類する。メソッド、関数、属性、引数、クラスを区別する。詳細では目的、入力、返り値、shape、副作用、具体例、比較、公式仕様を扱う。

掲載範囲と対象版を明示し、選集を「完全な一覧」と呼ばない。継承する機能は共通の基底クラスへつなぎ、同じ解説を複製しない。

追加トークンは表記・ID・用途・specialフラグを別の軸として持つ。Added Token、special=True、EOS/PADなどの役割、モデルの能力を混同しない。

## 特に維持する区別

- 文字数、UTF-8バイト数、トークン数。
- 生の文字列、内部トークン表記、ID。
- Tokenizerの語彙数とモデル側の語彙サイズ。
- shape、軸の本数、全要素数。
- デバイス変更、dtype変換、shape変換、Embedding。
- 変数名、参照先のインスタンス、返り値、画面への出力。
- Embeddingの固定表現と、文脈を反映したhidden state。
- 学習モードの切替、勾配記録、勾配計算、重みの更新。

疑問への回答は、それが必要になる本文の位置へ置く。最後の比較表やFAQだけで、本文の説明不足を補おうとしない。

## Pythonの構文とライブラリをつなぐ

重要な呼び出しを初めて扱うときは、ドットの左側が何を参照するか、右側が属性・関数・クラス・メソッドのどれか、呼び出し後に何が返るかを説明する。importの書き方や名前の大文字・小文字だけを、種類の判定規則にしない。

クラスの説明は、引数から属性への保存、同じクラスから作った複数の実物、メソッドを呼んだ際のselfを小さな例で結びつける。一般的なPythonの説明は基礎単元で扱い、TokenizerやEmbeddingでは現在のコードへの対応を短く示してリンクする。

同じ数値が異なる役割で登場する場合は、値・型・shape・軸の意味を並べて比較する。IDEの静的な表示と、実行時にtypeやinspectで確認した情報も分けて扱う。

過去の会話は疑問や理解の経路を把握する資料として使う。途中の誤説明は後続の訂正と公式仕様に照合する。長い会話の参照では、取得できた始点・終点、分岐元との重複、添付画像など未確認の範囲を記録してから網羅性を判断する。
