# プロダクト方針

## 目的と対象

LLMの文章入力から内部計算・生成・学習・改造までを、説明・操作・コードを往復して理解する日本語の学習サイト。最終的な学習目標は、変更箇所・理由・結果を説明できるモデル改造である。

Pythonの初歩に触れた読者を想定する。GPU、特定の学習履歴、高度な数学を一律に前提とせず、必要なPythonと数学を関連する箇所で説明する。

## 四つの入口

| 入口     | 主な用途                 | 構成                                      |
| -------- | ------------------------ | ----------------------------------------- |
| 学ぶ     | 前提から理解する         | 学習マップ、29単元の本文、確認問題        |
| 実験する | 条件の変化を観察する     | 12の操作教材                              |
| 調べる   | 名前・目的・表記から引く | ライブラリ別API、用語、比較、特殊トークン |
| 改造する | 理解を実験へ適用する     | 前提・手順・コード例・確認項目を持つ6課題 |

周辺技術には、実行基盤、再現性、保存形式、推論エンジン、RAG、Tool Use、性能測定などを含む。

## 情報構造

上部の主要ナビゲーションと、左側のローカルナビを分ける。左側は現在のセクション内の項目へ移動する。教材・API・実験・課題を行き来する関連リンクは本文にも設ける。

API辞書は `PyTorch / Transformers → モジュール・クラス → 用途別の機能 → 詳細` の階層を保つ。異なる所有者のAPIを一つの長い表へ混在させない。本文検索の結果ではライブラリや所有者を添えて文脈を伝える。

## 学習体験

一つの対象の準備・確認コード・出力・性質の読み取りを近くに置く。異なる処理はそれぞれの結果と組にする。値とshapeを同時に比較できることを、装飾より優先する。

実験は入力を変えて結果を観察するためのもの。PyTorchをブラウザーで実行していない実験を、そのように見せない。理解確認にはshapeの予測、似た操作の比較、結果の理由を使う。

## 現在の機能の境界

静的サイトとして配信し、ログイン・DB・任意Python実行サーバーは使わない。テーマ選択は端末内に保持する。読了・ブックマーク・学習進捗の追跡は採用していない。新機能として再導入する場合は、別の要件として判断する。

通常の閲覧でモデルの重みを取得しない。ブラウザー内での説明用計算と、読者がPython環境で実行する実モデルの課題を区別する。
