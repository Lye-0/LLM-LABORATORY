# 動きで学ぶ：連続する時間軸と表示の意味

## 表示と操作

「文章を通す」の01入力、02 Decoder、03出力、04生成に対応する4区分・29工程を一本の時間軸で表現する。中央のパーツは固定IDを持ち、直前の結果を次の開始状態へ渡す。下部の工程一覧・再生位置・速度・前後操作は画面に追従する。前後操作は現在時刻から工程境界まで再生して停止する。独立した工程ごとの位置リセットやプルダウンは設けない。

Token分割は同じ文字へ境界を入れて間隔を開く。Kの転置は各要素の行列添字を交換し、RoPEの回転と区別する。通常の計算は移動が99.5%以上進んだ58%から開始し、86%以降は結果を読む時間にする。新しい結果の直後のRMSNorm・down_projは開始後8%を保持、64%まで移動、65〜92%を計算に使う。残り27層は開始後4%を保持、16%まで移動し、20〜94%の間で層の計算を繰り返す。移動中に次の層の値へ変わらないよう、層番号と反復計算も同じ時間配分に従う。Embeddingは位置合わせの終盤である80%から更新する。値は行ごとに切り替え、架空の中間値を補間しない。

## 数値の範囲

Token IDとEmbedding先頭3成分は固定revisionのQwen3-0.6Bの観察fixture。その後はhidden幅3・MLP幅6・Q 2 Heads（各3成分）・共有KV 1 Head・3候補の説明用モデルで計算し、実モデルの1024成分のForward値と区別する。RMSNormの係数は1、εは1e-6。数値は計算後に表示上で丸める。

全28層の値、Residual、Q/K/V、RoPE、scores、mask、Softmax、加重和、射影、MLP、logits、選択IDは、前の結果を使って実際に計算する。KV Cacheの「新」や各層の位置番号は構造図であり、新しい位置の数値を実測した表示ではない。ID追加の時点ではCacheは増えず、次のForwardで新しいK/Vが追加されることを説明する。

## 入力・重み・出力を混同させない

Q/K/Vは共有入力Xから別の重みへ分岐する。重みと出力の中心を揃え、式は対応するQ・K・Vの横へ配置する。Gate/Upも重みを行列として表示し、各分岐の下に対応する式を配置する。KやUを重みとして扱わない。

o_proj、down_proj、LM headでは、左の入力を参照用に保持し、中央の重みと掛けて右の出力を作る。出力の値へ変わった行列に「×重み」だけを添え、再び入力として掛けているように描かない。構築中の出力は完成済みの行だけ値を出し、未計算の行は点で示す。結果を保持する同じパーツを次へ渡す。新しく使う重みは最初から正しい値と寸法を持ち、非表示だった前の重みを表示しない。

Residualと要素積は、入力を残し、別の結果行列を作る処理として説明する。保存した値と演算に使う値を離し、使用時には保存値の名前を消さない。加算後のH₂と層の出力H⁽¹⁾が同じ値であることを説明する。Q/K Normの式は同じ記号への更新を表す←を使う。scoresの図にも1/√dをMathMLの分数で表示し、Q×Kだけの結果に見せない。

## 保存領域と説明

左の待機・保存領域を主計算から点線で区別する。Residual用入力、加重和を待つV、要素積を待つUを置き、現在の演算に含まれないことを短く表示する。使用時は主計算へ移動する。Qを先に退避させてからKを移動・転置するなど、並列の要素が互いを横切らない経路を使う。

行列上には名前と状態を置き、処理の式は別の場所へ置く。分数・根号・添字・指数はMathMLで組版する。説明を移動経路の外へ一律に追いやると、式と演算の対応や読む位置を失うため、完成時の対応先に位置を固定する。行列が説明位置を通る間だけ、重なる前から説明を薄くして隠し、通過後に戻す。完了時に説明が隠れていないことも検査する。

並列処理を増やすときは先に必要な描画高を確保し、途中の行列が図の外へ描かれないようにする。高さを減らすときは、待機する値や退場する値が収まる経路と順序を使う。小画面では図だけを横スクロールし、ページ全体を横へはみ出させない。

## 強調の意味と生成後半の連続性

オレンジは処理への参加を示す。全工程へ同じ「行を移動しながら成分0を選ぶ」規則を適用しない。転置で位置を変えるのはKの要素だけで、Qを走査しない。説明モデルは2 Headの結果をTokenごとに横へ連結する。連結は並べ直しなので算術の走査をしない。RMSNorm・Residual・要素積は処理する行の全成分を強調する。RoPEは回転する2成分だけを対象にし、実際の入力ベクトルの向きから位置の角度だけ回す。終了時に図の向きがゼロへ戻らないようにする。

行列積は出力の一行をバッチとして計算し、対応する入力の行・重みの全列・出力の全成分を強調する。Vの加重和では、因果mask後に有効な位置の全列を使うことを示し、未来の割合0の位置は寄与しない。数値例は成分0の例であると明記する。行の値は計算が終わってから全成分をまとめて出し、処理時間も読み取れる長さへ調整する。

射影では元の入力パーツをそのまま左へ移動し、出力は別の空のパーツから作る。入力値を出力へ一時的に複製しない。o_projの入力C、down_projの入力M、LM headの入力Hfinalについて、開始から完了まで同じ入力DOMが保たれること、出力は空から始まることを検査する。工程をまたぐパーツIDはjourney-actorsのactorIdとprojectionActorsで解決する。作成された出力のIDを次の工程の入力として引き継ぐ。

生成後半は、末尾のLogitsの抽出→Softmax→GreedyでID選択→保持した7個のIDへ1個追加、を順番に表示する。確率ができる前に次のIDを表示しない。保持した入力IDは文字と対応付けたカードで示し、選んだIDが末尾へ移動する。Cacheでは保持済みの7位置の値を最初から表示し、過去の値を点から再構築したり走査したりしない。新しい1位置だけを、次のForwardからの矢印と追加の表示で表す。decodeも同じID列からToken順に文字列へ戻す。

追加検証は、強調する成分の数と意味、無処理で走査しないこと、重みの全列、入力の単一性、確率とID選択の時間順序、過去Cacheの非再生成、RoPEの最終角度を対象とする。配置の非重複だけで理解しやすいと判断せず、実際の途中表示と前後の意味を照合する。

要素積M = Gₐ ⊙ UとResidual ①・②は、入力2つを残して右に別の結果行列を作る。結果は空のセルから行単位で構築し、入力の値は変更しない。完成したM・H₁・H₂の同じパーツを次工程へ移動して使用する。binaryActorsで入力2つと出力のIDを解決し、表示・強調・後続工程への継承を一致させる。途中で入力を結果名へ変更したり、結果の場所へ入力値を複製したりしない。


## 数値表示と形・軸表示

下部の固定コントロールに「数値で見る / 形と軸で見る」を置く。初期表示は数値。view=shapesをURLで復元する。表示切り替えは時刻・再生状態・速度・行先を変更しない。数値Canvasは同じDOMのまま保持し、元の小モデルの計算やタイミングを変更しない。

形表示はjourney-shapesの独立した寸法・軸データを使う。Qwen3-0.6BのBatch 1・7 Tokenを想定し、長方形の縦横比は模式的。内部のセルや数値例の要素は描かない。実モデル全体の数値計算を実行したとは表示しない。Q/K/VのHead分割後は1 Headを表示し、Q 16 Heads / KV 8 Headsの対応を併記する。Head連結は他の15 Headも加わることを示す。

QK転置の積は7×128と128×7から7×7へ、Softmax後の割合とVの積は7×7と7×128から7×128へ。前者はスコア、後者の前にMaskとSoftmaxを通した参照割合がある。内側の軸を強調し、Query位置・Key位置・成分の違いを短い軸名で示す。要素積・Residualは縮約せず同じshapeの新しい結果を作る。LM headは1024×151936の重みから7×151936の候補スコアへ写す。151936はモデルの出力候補数で、Tokenizerの語彙数と同一視しない。

形表示専用の配置を前後の工程間で補間し、パーツIDと全体時刻は共有する。退場する入力は次の入力の移動経路へ残さない。新しい重みは登場時から正しい寸法を使う。保存する枝は保存元の位置から始め、待機中は小さく分ける。数値表示と異なる配置が必要な場面でも、工程を先頭から再生し直さない。

追加の単体検証は実寸法の積の整合、同じパーツの工程境界の配置継承、待機領域の寸法、表示範囲を対象とする。ブラウザ検証は全29工程・数式の収まり・再生中の表示切り替え・速度と時刻・数値DOMの維持・URL復元・390px幅を確認する。検証画像とログは.cache内に保持する。


### 両ビューの共通表現と配置確認

Token・ID・分割線は数値ビューの描画を共用し、色、枠、文字サイズ、分割線の出現・消失を一致させる。選択IDとdecodeの結果は、形表示では実モデルの予測値と誤解させない抽象表現を保つ。行列の位置や軸に必要な寸法は各ビューに合わせる。

待機・保存の見出しと点線を共用する。形表示のRoPEは成分ペアへの回転を式と進行説明で示し、行列全体の転置スピンと区別する。形表示もQは青、K・重みは黄、保存値は紫、出力は緑で役割を区別する。保存値の用途を省略せず、使用する段階では主計算へ移動させる。

新しい行列は入力の移動が落ち着くまで表示を待つ。移動するパーツの軸・補足は出発後に薄くし、到着時に戻して文字が他のパーツを横切ることを避ける。Upの移動はGateの下を通す。長いHeadの補足は行列幅で折り返し、説明は移動中のToken・IDにも重ならない位置へ置く。

ブラウザー検証は共通描画の実際の色・枠・文字サイズ・位置と再生時刻を比較し、全29工程の8時点でラベル・軸・補足・説明の交差を検出する。数値の整合性と工程境界の継承は既存テストでも継続確認する。自動検査に加え、途中と完了の描画画像で意味と視認性を確認する。


### 行列全体の長方形と処理の意味

形表示には内部の小さなセル、行を走査する枠、Headの内部区切り、説明のない転置記号を置かない。行列全体の長方形に型を表示し、軸名と用途は外へ置く。保存領域への拡大縮小も同じ縦横比を保つ。行列積・要素積・Residualの出力は別の長方形として生成する。

転置のKは192×136の同じプレートを中心で0→90度へ回転する。位置の移動後に回転を進め、辺の長さを変形させない。文字は水平を維持し、回転中の軸名は薄くして完了時に交換後の型と軸を示す。次のscoresでも90度の向きを保持する。

Maskは処理前に斜線を出さず、処理の進行と連動して右上の連続した参照禁止領域を現す。これは要素の配置図ではなく未来のKey位置を示す模式図。Softmaxへの切り替えでも適用済みの領域を保持する。

RMSNorm、Q/K Norm、RoPE、転置、Mask、Softmax、SiLU、最終Norm、層の反復、候補選択には、処理名・組版した数式・処理前／中／完了・意味の説明を表示する。小モデルの数値を持ち込まない。色の面変化だけで処理内容を説明したことにしない。行列積の軸対応は軸名と式の同色強調で示す。

追加のブラウザー検証はセル・走査枠の不在、転置中の辺長と角度、後続への向きの継承、Maskの適用タイミング、単項処理の数式と状態を対象とする。全29工程の8時点で文字の重なりを検査し、数値ビューの既存検証も実行する。


### Headの分割・結合と表示スライス

共通の上部表示は「表示スライス：Batch 0 · Layer 0」とし、Head分割後の詳細経路にだけQ Head 0 / 全2・KV Head 0 / 全1（形ビューでは全16・全8）を添える。全Tokenを表示しているためToken範囲や計算中の行・成分は含めず、処理説明や次元数も別の説明に任せる。Head分割前・分割途中・全Headを結合する段階では、特定Headを切り出した表示と誤認させないようHead欄を省く。番号は0始まり、「全」は総数を表す。

数値モデルはQの射影を3×6、各Query Headを7×3とし、Headごとに正規化・RoPE・参照スコア・Mask・Softmax・共有Vとの加重和を計算する。2つの7×3の結果をTokenごとに連結した7×6を、6×3のo_projへ渡す。分割した成分を捨てたり、Head 0の結果を複製してHead 1としたりしない。以降の層・logits・候補選択も新しいモデルの結果を使うため、以前の1 Headモデルと生成結果が異なる場合がある。

分割の開始では、Q Head 1の値を元のQの後半3列と同じ位置に置き、別の経路へ移動する。詳細はHead 0を表示し、Head 1でも同じ処理が行われることを表示する。結合ではHead 0を先に整え、別経路で計算したHead 1の結果を同じ行の右へ移動する。結合済みの6成分を同じ位置から次のo_projへ引き継ぐ。形ビューは内部のセルを追加せず、Head 0・1・…・15の表示を寄せ、連結後の7×2048へつなぐ。

単体検証は分割・連結時の成分順、Head内の個別正規化、共有K/Vからの独立したAttention、o_proj入力を検証する。ブラウザーでは分割開始の値と座標の一致、結合後の行の一致、6成分の継承、表示スライスと再生時刻の保持を確認する。


### スライス表示の配置とタイムライン連動

上部は中央揃えの固定2段。1段目はBatch・Layer、2段目はQ/KV Head。分割後のHead名は行列の上方に現れ、行列の移動が落ち着いてから上部へ移動する。K側は保存領域と主処理の間を通り、Qの行列や右側の数式を横切らない。総数は到着間際に加わる。行列本体の座標・数値計算・データの継承は変更しない。

Head表示はRoPEから加重和まで位置を保ち、結合の開始でフェードアウトする。Batch・LayerはQ/K/V射影でフェードインし、o_proj完了時に消える。全ての位置・濃度を共通タイムラインから求めるため、停止・逆方向のシーク・ビュー切替でも再生をやり直さない。「動きを減らす」ではラベルの移動を省き、濃度だけを変える。
